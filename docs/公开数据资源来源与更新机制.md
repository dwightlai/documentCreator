# 公开数据资源来源与更新机制

更新日期：2026-10-29

## 范围与交付状态

本批数据包含 5 类、42 条来源卡片和 8 份离线保存的官方文件正文，对应 12 个不同的公开页面。卡片包含标题、发布机构、文号或公开日期、自行撰写的摘要、使用场景及原始网址。8 份正文保存在 [`offline/`](../platform-bootstrap/src/main/resources/public-data/offline/)；提取记录和内容校验值保存在 [`offline-manifest.json`](../platform-bootstrap/src/main/resources/public-data/offline-manifest.json)。

本批数据可在断网环境中检索来源卡片和已保存的 8 份官方文件正文。其他卡片只包含自行整理的摘要；标准信息页和机关文章未保存全文。这批数据不宣称覆盖全国、所有行业或现行文件的全部内容。文件的现行效力和适用范围须在联网的资料准备环节由人工复核，再将核验后的更新包导入隔离环境。公开的审校案例属于业务参考，不作为具有普遍约束力的现行规则自动发布。

## 离线正文的范围

8 份本地文本对应 `NORM-001`、`POLICY-001` 至 `POLICY-004`、`FACT-001`、`EXAMPLE-001` 和 `EXAMPLE-003`。文本只提取已登记公开页面中的正文区域，不访问登录页面、隐藏接口或其他网址。每份文本在 [`offline-manifest.json`](../platform-bootstrap/src/main/resources/public-data/offline-manifest.json) 中记录来源网址、提取日期、页面与文本校验值及正文选择器。安装时会再次核对文本校验值，并拆分为本地可检索的切片。

`EXAMPLE-001` 的公开页面注明「本文有删减」，因此离线文本也只覆盖该页面公布的内容。其他页面如有单独附件，当前文本仅覆盖网页正文区域。界面中的「公开页正文」表示本地保存的公开页面文字，不表示已取得原始版式文件或完成现行效力审查。

连接互联网的资料准备机可运行 `cd platform-web; node scripts/build-offline-public-texts.mjs` 重建这 8 份文本。脚本只访问清单内的公开政府 HTTPS 页面，并检查标题、正文长度和哈希值。重新提取后须人工比对页面变化，再发布新的安装包；隔离环境运行时不执行网络抓取。

## 如何进入产品

项目新增了版本化来源包和知识库安装接口：

- 本地开发环境启动时，为 `local-government` 租户安装五个知识库分类、42 条来源卡片和 8 份离线正文。
- 其他租户的管理员可调用 `GET /api/v1/knowledge/public-source-pack` 查询安装状态，再调用 `POST /api/v1/knowledge/public-source-pack/install` 安装。
- 安装按版本记录，重复调用不会重复创建条目，也不会覆盖租户在界面中修改过的卡片。
- 每张卡片作为一条可检索知识文档，原始网址、发布机构、文号和核验日期保存在文档元信息中。有本地正文的卡片附一段原文摘录；没有本地正文的卡片明确标记为「仅来源索引」。

在产品的「知识与依据中心」打开「公开数据资源」，按分类查看资料。含摘录的来源卡片提供「查看本地原文」按钮；在卡片切片弹窗中也可点击「查看对应的本地原文」。标题标记为「公开页正文」的文档可通过「查看切片」在断网状态下阅读；「查看来源」展示出处信息。原文网址只是溯源标识，隔离环境无需访问该网址即可检索已保存的正文。

这批资料尚未自动接入正文生成，也未将案例直接升级为自动审校规则。写作问答可检索本地切片；将某项政策表述用于正式生成或审校前，仍需由资料维护人员核实适用范围和时效。

## 持续更新机制

[`check_public_sources.mjs`](../tools/check_public_sources.mjs) 只访问来源包登记的 12 个公开 HTTPS 政府页面：

1. 每个网址最多读取 2 MB 页面内容，并限制超时及重定向目标域名。
2. 从公开页面提取可见文字，检查登记的标题或核验文字是否仍出现。
3. 首次成功访问建立内容指纹基线，后续访问与基线比较。
4. 页面变化输出「待复核」，访问失败输出「访问失败」；保留原基线，不自动改写知识库。
5. 人工核验文件修订、替代、废止与适用范围后，更新来源包版本，重新安装或修改条目，并记录审核结果。

工作流 [`.github/workflows/public-source-monitor.yml`](../.github/workflows/public-source-monitor.yml) 配置为每周一 09:20（北京时间）运行一次，并允许手动触发。它上传 JSON 报告；遇到页面变化或访问失败会标记作业失败，供维护人员处理。工作流只有仓库发布到 GitHub 且启用 Actions 后才会实际定时运行。

本地也可执行：

```powershell
node tools/check_public_sources.mjs
```

在 Windows 主机上，可执行 `powershell -File tools/register_public_source_monitor.ps1`，为当前主机注册每周一 09:20 的计划任务。该任务调用本机 Node.js，运行后将状态与报告写入项目的 `data/public-source-monitor/`。主机需在计划运行时联网；失败或变更仍需维护人员查看报告。

本工作区所在 Windows 主机已注册 `DocumentCreator-PublicSourceMonitor` 计划任务。2026-10-28 手动触发一次后返回成功；下一次计划运行时间为 2026-11-02 09:20（北京时间）。计划任务与 GitHub Actions 为两种运行方式，可按部署环境选择保留。

默认状态与报告保存在 `data/public-source-monitor/`，该目录为本地运行数据。人工核实页面变更，并完成来源包修订后，可通过 `--accept-url <登记的公开网址>` 接受本地已观察到的内容指纹。此操作只更新本地监测基线，不修改产品知识库。

页面内容变化可能由网站导航、发布日期展示或模板更新引起，需要人工判断。旧页面不变化也不能证明没有新规取代它。因此维护人员还应定期核查[国务院政策文件库](https://sousuo.www.gov.cn/zcwjk/)和[国家行政法规库](https://xzfg.moj.gov.cn/)等公开目录，登记新发布或废止文件。上述目录为公开页面；当前工作流未自动发现目录中的新文件。

## 后续扩充要求

每新增一批来源，须保存公开网址、发布机构、文号或日期、核验日期、内容摘要、适用范围和人工审核记录。来源失效时应在产品中标注并限制用于新写作和审校；不得仅因网页返回错误就推断法律效力终止。

此批 42 条是可核验的首批资源，距离完整覆盖仍有差距。扩充时优先按文种、地区和行业建立明确的覆盖目录，再逐项核验和发布。
