# 公文写作平台同行产品对比与数据、模型建设建议

编制日期：2026-10-28  
文档性质：产品建设建议，供确定后续建设范围和实施顺序使用。  
范围说明：本文整理已完成的产品资料对比与当前项目核查结果。文中的建设方案均为建议，不表示相关数据已采集、能力已实现或效果已通过验收。

## 1. 对比依据与结论

### 1.1 对比资料

本次参考以下两份产品介绍，两份材料均来自方寸智能，并非两家独立厂商的产品：

- [产品介绍-逐字稿版本.pptx](D:/workspace3/archiveReasearch/同行产品介绍/产品介绍-逐字稿版本.pptx)
- [（0620）方寸智能-公司业务与产品介绍.pptx](D:/workspace3/archiveReasearch/同行产品介绍/（0620）方寸智能-公司业务与产品介绍.pptx)

材料展示了公文检索、写作、审校、排版、知识库、领域模型、办公软件插件及 OA 集成等能力。逐字稿版本重点参考第 8—14 页；公司业务与产品介绍重点参考第 8—16 页、第 24—27 页。

材料中的语料规模、审校分类数量和准确率属于厂商自述，部分数据口径存在差异，尚未独立验证。本文将其作为产品方向参考，不将宣传数值直接作为验收基准。

### 1.2 核心结论

当前平台应优先建设权威数据资源、持续更新机制、数据与业务的结合及效果评测，再开展有针对性的模型微调。

建设目标是让写作和审校具备以下能力：

- 每项依据可以追溯到原始出处。
- 每条规范和政策可以判断版本、适用范围与有效状态。
- 写作时能够检索并引用已授权的有效材料。
- 审校结论能够说明问题、依据、适用条件与修改建议。
- 模型、规则和数据升级能够通过独立评测说明实际效果。

## 2. 能力差距与完善方向

| 方向 | 同行材料展示的能力 | 当前项目情况 | 建议建设内容 | 优先级 |
| --- | --- | --- | --- | --- |
| 权威数据资源 | 政策、公文、重要表述、审校案例等多类资源 | 已有规范基础包和知识库，尚未形成持续运营的数据资源体系 | 建设规范、政策、事实、范例、纠错案例等数据资产 | 最高 |
| 数据持续更新 | 按事件、周、月等节奏更新，提供私有化更新服务 | 主要依靠预置数据与人工上传 | 建设采集、核验、版本发布、失效、更新与撤销流程 | 最高 |
| 写作与知识结合 | 检索、问答、依据写作相互衔接 | 正文生成主要使用任务信息和已关联材料，尚未自动检索知识库补充依据 | 按章节检索依据，生成时引用来源，提示无依据事实 | 最高 |
| 审校深度 | 规范表述、事实、政策等多类检查 | 已有规则与词库机制，权威事实、时效及业务依据不足 | 增加有效性核验、名称和称谓核验、政策引用及业务规则检查 | 最高 |
| 效果评测 | 强调准确率、专家经验与纠错案例 | 已有工程测试，缺少独立标注数据集证明实际准确率 | 建设标准答案、评测集、误报案例和回归评测机制 | 最高 |
| 专用模型 | 宣称开展领域预训练和微调 | 当前主要是模型接入、路由、提示词及推理调用 | 建设训练数据管理、微调试点、评测及模型版本管理 | 高 |
| 文档综合处理 | 跨文档比对、查重、要素提取、OCR 等 | 已有解析和版本比较，跨库查重及复杂文档理解仍可加强 | 按实际业务补充跨文档处理能力 | 中 |
| 办公集成 | Web、办公软件插件、API、OA 场景 | 已建设平台及开放接口 | 按客户需求补充办公软件插件和 OA 业务集成 | 中 |

## 3. 当前基础与主要限制

### 3.1 规范数据包

当前[规范基础数据包说明](official-review-pack.md)记录了 6 部词库、422 个词条和 60 条审校条款。其中，4 条适合按文本表达式自动提示，56 条需要结合版式、上下文、行文关系或业务事实进行人工核验。

该数据包是依据公开规范整理的可追溯初始数据，不是规范发布机关发布的标准文本，也不能据此宣称已经具备全面自动审校能力。

### 3.2 知识参与业务

平台已经具备知识文档导入、切片、检索及权限过滤基础。当前正文生成主要使用任务信息和已关联材料；依据问答主要检索并展示来源片段。自动检索、引用、有效性核验与生成的衔接仍需完善。

### 3.3 模型与评测

当前模型能力主要由模型网关接入的推理服务提供。模型接入和路由不等于已经具备模型训练能力。

现有[验收矩阵](acceptance/V1_6_ACCEPTANCE_MATRIX.md)明确记录，事实来源覆盖、DOCX 结构识别、审校精确率、召回率等仍需独立标注数据集验证。工程测试通过不能替代业务准确率验收。

## 4. 数据资源建设方案

### 4.1 建设五类数据资产

| 数据资产 | 内容范围 | 主要用途 | 维护重点 |
| --- | --- | --- | --- |
| 公文规范库 | 公文处理规定、格式标准、语言文字规范、地方细则、机构要求 | 文种、格式、行文关系及用语检查 | 适用条款、版本、例外、自动或人工核验方式 |
| 政策与规范表述库 | 官方政策文件、权威发布中的规范表述、适用范围及有效期 | 依据检索、政策引用、表述核验 | 发布机关、有效状态、原文与整理内容的区分 |
| 权威事实库 | 机构名称及简称、行政区划、职务称谓、业务术语等 | 名称、称谓、时间及事实一致性核验 | 时间范围、适用地区、来源与变更记录 |
| 优质公文范例库 | 经审核的公开公文及获授权的历史成文 | 结构、措辞、章节和场景参考 | 文种、业务场景、质量、使用授权与脱敏 |
| 审校纠错案例库 | 原文、问题位置、修改结果、原因、依据、语境及误报案例 | 规则改进、训练和效果评测 | 人工审核、正反例、适用条件及数据集隔离 |

### 4.2 明确“完整”的范围

完整性应按明确目录和版本验收，例如：覆盖指定版本规范的全部适用条款，或覆盖某地区、某行业确定的政策目录。

每个数据包应明确包含内容、未覆盖内容、来源、适用范围和维护责任。文档数量、词条数量可用于统计，但不能单独证明权威性、完整性和有效性。

### 4.3 统一数据元信息

| 类别 | 建议保存的信息 |
| --- | --- |
| 来源 | 发布机关、原始标题、原始链接、文号、原文或可核验的留存记录 |
| 时间 | 发布日期、施行日期、失效日期、最近核验时间 |
| 适用范围 | 地区、行业、机构、文种、业务场景、适用条件和例外 |
| 版本 | 数据版本、原文指纹、替代关系、修订记录 |
| 权限 | 使用授权、公开或私有范围、所属租户、访问权限、敏感级别 |
| 审核 | 整理人员、审核人员、审核结论、发布状态 |

公开可访问不应自动解释为可无限制批量采集、再分发或用于训练。应在来源登记时记录相应使用条件。

### 4.4 公开资源获取与持续更新

建议采用以下处理流程：

1. 建立权威来源目录，明确官方站点、标准发布渠道和获授权的数据来源。
2. 通过允许的接口、下载渠道或人工导入取得数据，保存原始出处和获取记录。
3. 完成解析、去重、分类和必要的 OCR，保留原文与整理内容之间的关联。
4. 核验来源、适用范围、有效状态和使用条件。
5. 由业务审核人员确认整理结果，发布数据版本。
6. 监测修订、替代、废止及机构变更，更新关联规则、词条和知识片段。
7. 对更新失败、来源不可访问及有效性待确认的数据建立待处理清单。

更新频率应按来源和业务风险确定。具体检查周期、处理时限和负责人需要在建设范围确定后落入运行制度。

### 4.5 数据包交付与人员分工

建议提供基础规范包、行业包、地方包和单位专用包，支持版本说明、增量更新、内网导入和回退。租户自行维护的数据需要保留，不应被公共数据更新直接覆盖。

开发人员负责采集、解析、检索和发布工具；数据编辑负责来源整理与元信息；业务审核人员负责适用性及结论审核。应明确持续维护责任，避免初次导入后无人更新。

## 5. 数据与写作、审校的结合

### 5.1 写作流程

建议让每个章节依次完成：

1. 根据写作目的、文种、地区、机构和章节内容形成检索条件。
2. 检索权限范围内、适用且有效的政策和材料。
3. 向生成模型提供来源片段及引用标识。
4. 对生成内容保存来源关联，区分引用事实、用户提供的数据和待核实内容。
5. 在编辑界面支持查看出处、定位原文和检查引用有效性。

例如，生成设备更新资金请示时，应关联适用政策和用户提交的预算材料，分别标明政策依据与预算数据来源。

### 5.2 审校流程

建议根据问题类型选择检查方式：

| 检查对象 | 建议方式 |
| --- | --- |
| 可确定的词形、符号及数值关系 | 使用规则或确定性计算，保留适用条件 |
| 机构名称、称谓、行政区划 | 查询适用时间范围内的权威事实数据 |
| 政策引用与规范表述 | 检索原文，核验版本、适用范围和上下文 |
| 文种、行文关系与业务事项 | 结合规则、材料和模型分析，必要时提示人工核验 |
| 证据不足的判断 | 明确提示待核实，展示缺失依据 |

每条审校问题应保存问题位置、检查来源、依据版本、建议和处理记录。用户的接受、拒绝或人工修改结果可进入候选案例库，经审核后再用于规则改进或训练。

## 6. 专用模型建设路径

### 6.1 先建立现有模型基线

先完善现有模型、提示词、检索增强生成和规则引擎之间的配合，并建立评测基线。检索增强生成适合处理需要更新和追溯来源的知识，相关研究见 [RAG 论文](https://arxiv.org/abs/2005.11401)。

持续变化的政策、机构名称和人员职务应由可更新的数据资源提供。模型微调主要用于改善结构、表达、分类和判断能力。

### 6.2 开展小范围微调试点

优先选择一个高频文种和一个审校任务，使用获准部署的基础模型进行领域微调。可评估 LoRA 等方法，以降低需要训练的参数量，相关研究见 [LoRA 论文](https://arxiv.org/abs/2106.09685)。

适合优先训练的任务包括：

- 按文种生成正确结构，减少章节重复和空泛表达。
- 学习经审核的机关写作风格。
- 识别文种、章节、公文要素及常见审校问题。
- 根据原文和规范依据生成清楚、克制的修改建议。

是否扩大训练范围，应依据相对现有模型的评测收益、数据质量、运行成本和部署条件决定。现阶段不建议直接启动从零训练基础模型。

### 6.3 建设训练与模型版本管理

至少记录基础模型、使用许可、训练数据版本、数据授权、训练参数、评测结果、上线版本及回退版本。

训练数据与评测数据应隔离；相同或近似公文应避免跨集合重复。单位私有材料应按授权和权限范围使用，跨租户训练需要明确的数据使用依据。

## 7. 效果评测与反馈闭环

### 7.1 建设独立评测集

从实际业务整理正确样本、错误样本和易误报样本，由业务人员确认问题位置、依据和标准答案。评测范围应覆盖约定文种、常见差错和高风险问题，并与训练数据隔离。

历史纠错记录不能未经核验直接作为标准答案。用户点击接受或忽略可作为反馈信号，仍需结合原文、语境和依据进行审核。

### 7.2 建议跟踪指标

| 建设内容 | 指标 |
| --- | --- |
| 数据资源 | 来源可追溯率、规范覆盖率、更新时延、失效数据比例 |
| 检索与引用 | 依据命中率、引用正确率、过期来源使用情况 |
| 写作 | 无依据事实比例、人工修改量、章节重复情况 |
| 审校 | 分类型精确率、召回率、严重问题漏报、每万字误报数 |
| 模型微调 | 相对基线的效果提升、响应时间、运行成本 |

具体阈值需要根据冻结样本和业务要求确定。不同问题类型应分别统计，避免总体平均值掩盖严重问题漏报或某一类型的高误报。

规则、词库、知识包、提示词或模型版本变化后，应运行对应回归评测，保存版本与结果的关联。

## 8. 建议实施顺序与交付物

| 阶段 | 建设重点 | 主要交付物 | 验证重点 |
| --- | --- | --- | --- |
| 第一阶段：补充数据基础 | 明确来源与覆盖目录，建设核验、版本、更新、失效和发布机制 | 来源登记表、数据目录、元信息规范、首批数据包、更新记录 | 来源可核验、范围明确、版本和有效状态可追溯 |
| 第二阶段：让数据参与业务 | 接通章节检索、政策引用、事实核验和来源定位 | 写作依据检索、引用展示、审校来源记录、反馈采集 | 来源权限、引用正确性、失效数据过滤和反馈可追溯 |
| 第三阶段：评测与模型试点 | 建立独立评测集，试点文种和审校任务微调 | 标注规范、评测集、基线报告、微调模型、对比报告和回退方案 | 相对基线的实际收益、误报漏报、运行成本与部署可行性 |

实施中应尽早收集评测样本，使评测工作与数据建设同步开展。阶段范围和验收条件确认后，再确定工期、人员和资源投入。

## 9. 后续建设范围的待确认项

- 首批覆盖的地区、行业、机构及业务场景。
- 首批政策、规范和事实来源目录。
- 数据使用及训练授权条件。
- 业务审核人员和持续维护责任人。
- 模型部署环境、算力条件及允许使用的基础模型。
- 冻结评测样本、指标口径和验收阈值。

以上事项用于界定可交付、可维护和可验证的建设范围。后续补充公开数据时，应按本文件的来源登记、审核及版本发布要求逐批交付。
