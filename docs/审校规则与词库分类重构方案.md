# 审校规则与词库分类重构方案

> 状态：待评审。本文只确定产品与技术方案，不代表已经修改审校功能。

## 一、结论

审校结果按公文业务问题分类；规则按所检查的问题归类；词库按所保存的数据对象组织。三者有关联，但不强制使用同一棵分类树。审校方案直接选择业务检查范围，不让用户选择 L1—L7。检查方法由规则和执行器决定，不充当问题分类。

现有 L1—L7 是代码中的检查层级和开关，并非公文审核标准要求的七级分类。新设计不依赖这组编号。实现时可先用适配层调用现有执行器，再逐步将运行开关改为稳定的能力代码；用户界面、持久化的新方案和开放接口均不再使用 L1—L7 作为分类。

## 二、业务分类

每条审校问题有一个主分类和一个具体问题类型。主分类用于浏览、统计和分配处理责任；问题类型用于准确描述命中原因。分类名称不等于系统能够自动作出最终判断。

| 主分类 | 典型问题类型 | 系统处理边界 |
| --- | --- | --- |
| 政治与重要表述 | 重要表述、领导人姓名职务、机构名称、固定提法 | 有经核验、带时效的依据时可提示不一致；敏感判断由人工复核 |
| 政策法规与事实依据 | 政策法规引用、条款时效、事实数字、来源缺失 | 能核对明确引用和本地权威数据；缺少依据时给出待核验提示，不推定事实错误 |
| 公文业务规范 | 文种选用、行文关系、主送抄送、请示与报告使用、办理要素 | 根据文种、行文方向和单位配置检查；涉及授权或程序的事项转人工 |
| 内容与逻辑 | 前后矛盾、要素缺失、语义歧义、措施与目标不一致 | 使用结构规则或模型提出核查建议，保留原文位置及判断理由 |
| 语言文字 | 错别字、异形词、病句、规范用语、不当用语、标点 | 确定性替换才允许自动修正；语境敏感的词项只提示 |
| 格式与版式 | 标题、发文字号、附件、版头版记、页面与段落版式、数字和计量单位形式 | 需基于可保留版式的文档结构；纯文本不能声称完成版式检查 |

保密要求不宜仅作为一个孤立的「敏感词」类：密级、知悉范围和外发限制涉及公文办理及安全控制。将此类规则归入「公文业务规范」，并另设「安全/保密」标签和权限控制。若以后形成独立的保密审查业务，再考虑增加独立主分类。

## 三、规则、词库和依据的关系

**审校规则**是一项可执行或可人工核验的检查定义，包含：规则代码、主分类、问题类型、适用文种/场景、触发条件、检测方法、风险等级、自动修正策略、依据版本、启停与审核状态。规则决定什么情况应生成问题。

**标准词库**保存可复用数据，如机构名称、职务称谓、重要表述、规范写法、易错词和地名。词条包含标准形式、别名、适用范围、生效与失效时间、来源和核验状态。词条本身不等于错误：正确名称命中时不应报错。一条规则可引用一个或多个词库；词库也可被多条规则使用。

**依据资源**保存可离线核对的法规、标准、政策及单位制度的原文和版本信息。规则和词条通过依据编号关联到具体条款或段落。外部网页地址只作为来源线索，不作为内网运行时唯一依据。

**审校问题**是一次检查的结果快照，保存规则/词条/依据版本、原文位置、触发片段、建议、检测方法、置信度和处理状态。编辑或重新审校文档时生成新的结果版本，不覆盖历史依据。

词库管理界面按「词库用途/数据对象」组织，例如机构与职务、重要表述、规范用语、地名、易错词；规则管理和结果页按六个业务主分类组织。词条可显示关联的业务分类，但不要求词库目录与六类一一对应。

## 四、审校方案与执行方式

方案配置选择需要检查的业务分类、适用文种、风险阈值、知识范围及可用检测能力。执行器根据已生效规则决定运行词项匹配、结构解析、版式解析、离线依据比对或模型辅助检查。规则属于哪个业务分类，与采用哪种执行器是两个独立字段。

这样，同属「公文业务规范」的文种检查和主送机关检查可以使用不同方法；同一词库也可服务于「政治与重要表述」和「公文业务规范」的不同规则。不得把六类简单映射成六个旧 L 编号，否则勾选分类后仍会运行其他类别的规则。

结果页按六类筛选，并保留「问题类型」「检测来源」「依据」「需人工核验」等字段。统计分清自动发现、人工核验建议和已确认问题。风险等级与分类独立，不以「政治」二字自动设为严重。

## 五、实施设计

1. 建立统一分类代码与问题类型字典。前后端使用稳定代码，界面显示中文名称；分类变更通过版本管理，不直接改历史记录含义。
2. 调整规则与词条数据模型。规则关联词库和离线依据；词条增加时效、核验状态、适用范围；检测方法与业务分类分列。
3. 调整审校方案接口和执行流程。方案存业务检查范围，执行器按已发布规则和能力调度；移除新接口中的 L1—L7 选择。现有执行器可暂时通过适配层复用，但结果必须按规则真实分类输出。
4. 重整预置规则与词库。逐条核定分类、适用范围、检测能力和依据；不可验证的示例词条不得作为权威词库自动生效。按本次要求，不为旧演示数据设计自动迁移或模糊映射。
5. 更新管理页和结果页。规则支持六类筛选及问题类型筛选；词库按数据对象浏览；结果展示定位、依据版本和人工核验标识。
6. 增加效果验证。分别验证确定性文字检查、文种/结构检查、政策事实比对和版式检查；报告每类覆盖范围、误报与漏报，不用未经验证的准确率数字。

## 六、验收标准

- 新建规则选择业务主分类、问题类型、检测方法和依据；分类与方法可自由组合。
- 新建词条不自动生成审校问题；只有已发布规则引用它并满足条件时才产生结果。
- 审校方案不出现 L1—L7；关闭某业务分类后，该类规则和模型建议均不生成问题。
- 每条问题可追溯到原文位置、检查来源、规则或词条版本及离线依据；不能确认的判断明确标为「需人工核验」。
- 导入、导出保留分类代码、关联关系和版本；无效分类或缺失依据给出明确校验结果。
- 离线部署断网后，已装载的规则、词库、依据和审校流程仍可使用。

## 七、依据与限制

《党政机关公文处理工作条例》将文稿审核覆盖行文理由、政策法规符合性、现行公文衔接、文种与格式等事项；《党政机关公文格式》GB/T 9704—2012 提供版式依据。本方案据此组织业务范围，但六类是本产品的管理设计，不宣称是国家标准规定的分类。政治、法律、事实及保密判断仍需要可靠的本地依据和人工责任人。
