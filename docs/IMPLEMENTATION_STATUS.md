## 编辑器与定稿决策（2026-10-23）

- **编辑方式**：写作阶段默认使用内置富文本编辑器（TipTap，按段落存储），保留段落锁、编辑租约、AI 来源标注与不可变版本；ONLYOFFICE 用于套红后的定稿稿在线微调，生产部署默认启用（`compose.yaml` 含文档服务器，前端 `/office/` 同源代理）；本地开发环境默认关闭。
- **多人实时协同**：暂不实施。设计 §14.4 要求“禁止多人同时覆盖同一段落（段落级临时锁定 + 乐观锁）”，实时协同需先调整该原则。
- **ONLYOFFICE 许可**：已确认可接受社区版 AGPL v3 许可及同时编辑连接数限制（仅通过接口集成，不修改其源码）。
- **信创**：当前不作为约束。日后提出信创要求时，以 WPS 中台替换 ONLYOFFICE：在线编辑仅通过 `platform-document` 的 `onlyoffice` 适配层（编辑器配置、文件拉取、保存回调）与前端 `OnlyOfficeEditor` 组件接入，定稿稿的生成、存储、格式检查与业务流程不依赖具体编辑器，替换时只需新增对应适配实现。
- **待确认**：公文字体（仿宋_GB2312、方正小标宋简体等）是否已取得授权并可安装到文档服务器；确认前在线编辑以替代字体显示，版式需以下载的 DOCX 为准。

“最终部署上线”只有在本表所有行完成、V1.6 第 36—37 节验收项全部取得证据后才能判定完成。

## CLOB 兼容约束

所有结构化数组、规则配置、版本快照和大段文本在领域模型中统一视为逻辑 `CLOB`，不依赖 `JSONB` 或数据库 JSON 运算符。当前 PostgreSQL/H2 基线以 `TEXT` 作为物理大文本类型；MySQL 部署应映射为 `LONGTEXT`，Oracle/达梦部署应映射为原生 `CLOB`。JSON 只作为 CLOB 内部的交换编码，由 `JsonClobTypeHandler` 在 Java 层序列化和反序列化。
